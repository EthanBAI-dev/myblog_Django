# 个人网站制作教程：从想法到上线

> 人人都能拥有自己的网站，现在比任何时候都简单。

---

## 一、你需要哪种网站？

先别想技术，先想清楚你要什么。

### 三种常见个人网站

```
个人网站
 ├─ 静态展示站 —— 展示项目、作品集、简历
 ├─ 博客          —— 写文章、记录思考、分享知识
 └─ 组合型      —— 首页展示 + 博客功能
```

### 怎么判断？

问自己一个问题：

> **我有没有想要记录和分享的内容？**

- **有** → 做博客。你做了一个项目、读了一本书、有了一些思考，想要写下来告诉别人。
- **没有** → 静态展示站就够了。放上你的项目链接、个人简介、联系方式。

> 如果一开始不确定，可以先用静态站。以后想写东西了，随时可以加上博客功能。

## 二、一个网站需要哪些东西？

很多人被"前端""后端"这些词吓住了。其实很简单：

### 用餐馆来理解

```
网站 = 一家餐馆
 ├─ 前端 = 大堂、装修、菜单、你看到的一切
 │    ├─ 桌椅摆放、灯光氛围 = CSS（样式）
 │    ├─ 菜单上的菜品分类 = HTML（结构）
 │    └─ 服务员招呼你、带你入座 = JavaScript（交互）
 │
 └─ 后端 = 厨房、仓库，你看不到但决定一切的部分
      ├─ 冰箱里的食材 = 数据库（存文章、用户信息）
      ├─ 厨师做菜的流程 = 服务器逻辑（注册、登录、搜索）
      └─ 水电燃气 = 服务器（24小时运转的后勤保障）
```

### 个人网站最少需要：

| 元素 | 说明 | 必须吗？ |
|------|------|----------|
| **域名** | 网站地址，比如 `yourname.com` | 推荐 |
| **前端页面** | 首页、关于页、作品展示 | ✅ |
| **样式** | 好看的颜色、排版、动画 | ✅ |
| **托管服务** | 让网站24小时在线 | ✅ |
| **数据库** | 存储文章、评论 | 博客需要 |
| **后台** | 写文章的管理界面 | 博客需要 |

## 三、现在做网站有多简单？

以前做一个网站需要：
1. 学 HTML / CSS / JavaScript
2. 学框架（React / Vue / Django）
3. 学服务器部署
4. 配域名、配 HTTPS

现在有了 **Vibe Coding**（用 AI 写代码），流程变成了：

```
有一个想法
    ↓
用自然语言描述给 AI（比如 "帮我做一个个人主页"）
    ↓
AI 生成代码
    ↓
调整修改
    ↓
一键部署
```

**难点不再是技术，而是想法。**

> 如果你不知道想做什么，就先去看别人的网站。

## 五、关于样式

### 先说一个最重要的观点

> **网站是给别人看的，内容才是核心。花里胡哨的样式没有用。**

看看这个大佬的网站：\[大佬网站链接\]

它可能没有什么炫酷的动画、复杂的布局，但内容扎实，读起来舒服。这就是好网站。

> 样式是服务于内容的。先把内容写好，样式只要做到"干净、易读"就够了。

### 如果你想更进一步

如果你已经不满足于"干净易读"，想做出更有质感的网站，可以参考下面的方法：

```
第 1 版：参考别人的布局，把功能做出来
     ↓
第 2 版：换一套颜色，改一下字体
     ↓
第 3 版：调整间距，加一点动画
     ↓
第 4 版：重新布局，换一种风格
     ↓
……一直改到第 20 版
```

**给自己定一个目标：改 20 个版本。**

不是一次改完，而是隔一段时间就重新设计一次。每次都有进步。

### 具体怎么改？

1. **参考 → 复制 → 创新**
   - 先模仿你喜欢的网站布局
   - 理解它为什么好看
   - 然后加入自己的东西

2. **让 AI 帮你生成样式**
   - "给我 5 种不同的配色方案"
   - "把这个页面改成毛玻璃风格"
   - "让导航栏更现代一点"

3. **换字体就能改变气质**
   - 中文字体推荐：思源黑体、Noto Serif SC
   - 英文字体推荐：Inter、JetBrains Mono

4. **极简永远不会错**
   - 留白多一点
   - 颜色少一点（不要超过 3 种主色）
   - 字间距、行间距调舒服

## 六、常见的坑（千万别踩）

做网站的路上，大多数人放弃不是因为难，而是踩了这几个坑。

### 坑零：忘了做网站的目的是什么

> 做个人网站是为了**展现自己，让人印象深刻**。

你做了什么项目、有什么思考、擅长什么——通过网站呈现出来，让看到的人记住你。

但有一句话你要记住：

> **打铁还需自身硬。**

网站只是一个展示柜，里面的东西才是关键。如果你没有项目可展示、没有内容可写，那网站再好看也是空的。

**正确的做法：**

```
先有内容（项目、作品、思考）
    ↓
再做网站（把它们展示出来）
    ↓
持续更新（内容越来越多，网站越来越丰富）
```

> 下面几个坑，根源都在于把这个顺序搞反了。

### 坑一：想打好基础再开始

> "等我学完 HTML、CSS、JavaScript、React、Django……再开始做。"

**结果**：学了一个月又一个月，基础永远打不完，项目从来没开始。

**正确的做法**：

```
想要的效果 → 查一下怎么做 → 做出来 → 遇到不会的 → 现学现用
```

> 不要"先学再做"，要"边做边学"。你需要的是够用就行，不是精通才动手。

### 坑二：学了一堆，没用上

> 花了三周学完了 React 全家桶，最后选了一个静态模板改改就上线了。

**结果**：学的东西全忘了，热情也耗尽了。

**正确的做法**：
- 做之前先想清楚：这个网站需要什么？
- 静态站？那就不需要学后端。
- 博客？Django 或 WordPress 选一个就够了。
- **只学你当下需要的，其他的遇到了再学。**

### 坑三：技术太多，眼花缭乱

打开搜索引擎一搜，做网站的技术能有几十种：

```
前端：React、Vue、Svelte、Next.js、Nuxt、Astro、Hugo……
后端：Django、Flask、FastAPI、Spring Boot、Express、Ruby on Rails……
数据库：MySQL、PostgreSQL、MongoDB、SQLite……
部署：AWS、Vercel、Netlify、PythonAnywhere、Railway……
```

**结果**：直接看晕了，不知道选哪个，干脆不做了。

**记住一句话：万变不离其宗。**

不管什么技术，本质都一样：

| 层 | 本质 | 不管换什么框架 |
|------|------|---------------|
| 前端 | 显示页面、处理用户操作 | 都是 HTML + CSS + JS |
| 后端 | 处理数据、业务逻辑 | 都是接收请求 → 处理 → 返回响应 |
| 数据库 | 存数据 | 都是增删改查 |

> **选一个你最熟悉的语言，用对应的生态就够了。** 会 Python 就用 Django，会 JS 就用 Next.js。技术是工具，不是目的。

### 坑四：想无中生有，自己搞样式

> "我要设计出一个独一无二的网站，和别人都不一样。"

**结果**：盯着空白编辑器一下午，一个字写不出来。

**正确的做法**：

```
先抄 → 再改 → 形成自己的风格
```

- 看到一个好看的导航栏？抄过来。
- 看到一个喜欢的配色？抄过来。
- 看到一个不错的布局？抄过来。

> 抄不是抄袭，是学习。把多个你喜欢的设计合并在一起，改成自己的内容，慢慢就有自己的风格了。

**给自己定个目标：改 20 个版本。**
第一个版本可能很丑，没关系。第 10 版会好一些，第 20 版就是你喜欢的了。

---

## 七、总结

```
做网站的正确顺序：

1. 想清楚要什么（静态站还是博客）
2. 去参考别人的网站，找到灵感
3. 用 AI 快速生成第一版
4. 上线，让别人能访问
5. 持续改版，目标是改 20 版
6. 慢慢形成自己的风格
```

> 不要等到"完美"才上线，先做出来，再慢慢改。
> 完美不是设计出来的，是迭代出来的。

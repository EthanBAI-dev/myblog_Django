# 用 Vibe Coding 做多语言网站，我是怎么用一条规则解决翻译混乱的

> 当你的网站要从一种语言变成三种语言，混乱就开始了。

---

## 从"中文就行"到"怎么还要翻译"

做这个博客网站最初的想法很简单：中文写文章，中文用户看，一切用中文。

后来发现不行。

一是认识一些不会中文的朋友，二是觉得自己做的项目应该让更多人看到，三是也想练练英文和日文写作。于是决定：**中英日三语同步**。

然后就踩坑了。

---

## 混乱是怎么开始的

一开始没有规则，想到什么改什么。

改导航栏的"关于"为"关于我"——只改了中文模板，英文和日文页面还是"About"和"について"。想的是"先改中文，回头再补另外两个"。

回头？再也没有回头。

一个月后看代码，`base.html` 里三处文字混合：中文硬编码、英文半翻译、日文没动。`.po` 文件里漏了十几条没翻译的条目。自己都分不清哪个是已翻译的、哪个是还没改的。

**这就是没有规则的结果。**

---

## 问题出在哪

用 Vibe Coding 做网站有一个特点：**快**。

你给 AI 说"帮我改一下导航栏"，它 10 秒就改好了。改完之后你看到效果不错，就去干别的了。至于英文和日文页面？忘了。

不是态度问题，是流程问题。Vibe Coding 让改代码变得太容易了，容易到你会忘记"改了中文还需要改另外两种语言"这件事。

而且 AI 不会主动提醒你——你让它改什么它就改什么。你说"把'关于'改成'关于我'"，它就只改这一处。它不知道你的网站有三门语言。

---

## 解决方案：一条规则

解决方式不是靠记住，是靠**规则**。

我写了一条规则放在项目的 `.trae/skills/` 目录下，让 AI 在执行任何修改之前自动参考。规则的核心就一句话：

> **改任何东西之前，先问自己：这个改动涉及几种语言？**

这条规则包含了几个部分：

### 1. 什么情况下要触发

不只是 UI 文字。以下改动都涉及语言同步：

- 改导航栏、按钮、标题等界面文字
- 修改或发布博客文章
- 新增页面模板
- 改页面上的说明文字

### 2. 改 UI 文字的标准步骤

```
改代码 → 运行 makemessages 提取翻译 → 编辑三个 .po 文件 → 编译 .mo
```

简单说就是：代码里用 `{% trans "xxx" %}` 或 `_('xxx')` 标记需要翻译的文字，然后用 Django 的命令提取到 `.po` 文件，逐条填翻译，最后编译。

### 3. 博客内容的处理逻辑

博客文章不是走 `.po` 文件的，需要手动维护三个语言版本：

```
blog/content/
├── zh-hans/article.md    ← 中文原文
├── en/article.md         ← 英文翻译
└── ja/article.md         ← 日文翻译
```

规则约定：**至少中文版要完整，英文和日文可以先写简版，但不能空白。**

### 4. 改完后的检查清单

这是一条"防呆"清单，每次改完对照检查：

- 三种语言都翻译了吗？
- `.po` 文件都填了吗？
- 编译成 `.mo` 文件了吗？
- 切换语言看了效果吗？

---

## 效果如何

把规则写进 skill 之后，再让 AI 帮忙改东西，它会自动按规则执行。

比如我说"把首页标题改成'探索日志'"：

以前：AI 只改中文 → 完工 → 英文和日文没动。

现在：AI 读规则 → 发现涉及多语言 → 改中文 → 提取翻译 → 等我填英文和日文翻译 → 编译 → 完成。

**从"靠人记"变成了"靠规则执行"。**

---

## 这些经验可能也适用你

如果你也在做一个多语言网站，不管用的是什么技术栈，以下几条建议可能有用：

1. **一开始就搭好翻译框架。** 哪怕你当前只需要一种语言，也把 i18n 的架子搭好。后面加语言是改配置，不是重构。
2. **把规则写在项目里。** 不要藏在某个文档里，要放在 AI 能看到的地方（比如 `.trae/skills/`、`.cursorrules`）。
3. **检查清单比翻文档快。** 每次改完对照几个 checkbox，比重新读一遍规则要高效得多。
4. **东西和人一样，会忍不住偷懒。** 不是态度问题，是流程问题。用规则代替记忆，用自动化代替手动。

---

## 附：规则文件放哪

我用的是 Trae IDE，规则放在：

```
.trae/skills/multi-lang-maintenance/SKILL.md
```

如果你用的是 Cursor，对应的是：

```
.cursorrules
```

或者你也可以直接写在一个 markdown 文件里，每次改代码前自己看一眼。关键不在工具，在**有没有规则**。

> 没有规则的多语言网站，三个月后连你自己都看不懂。😅

# Django ブログデプロイガイド：ゼロから自動更新まで

> 対象プロジェクト：myblog_Django (Django 6.0 + Python 3.13)

---

## 一、やること

### 目標

ローカルで作成した Django ブログプロジェクトをインターネット上に公開し、誰でもアクセスできるようにします。さらに、GitHub でコードを更新するたびに、サイトが自動で更新されるようにします。

### 目標の分解

```
最終目標：サイト公開 + 自動更新
 ├─ 第一步：コードを GitHub にアップロード（コード管理）
 ├─ 第二步：PythonAnywhere でサイトを作成（サーバー）
 ├─ 第三步：GitHub Actions で自動デプロイを設定（自動更新）
 └─ 完了
```

---

## 二、必要なもの（およびその説明）

### 1. 完成した Django ブログプロジェクト

あなたが開発している Django ブログプロジェクトです。記事、コメント、ユーザー管理などの機能を含みます。

> プロジェクトがまだない場合は、以前書いた Django ブログチュートリアルを参照してください：\[リンク先\]

### 2. GitHub —— コードを保管する場所

![](images/github-logo-placeholder.png)

- **説明**：コード管理プラットフォーム。クラウド上のコードのバックアップのようなものです
- **用途**：プロジェクトコードの保管、変更履歴の記録
- **必要**：GitHub アカウント（無料）

### 3. PythonAnywhere —— サイトを動かす場所

![](images/pythonanywhere-logo-placeholder.png)

- **説明**：クラウドサーバー。Python ウェブサイトを動かすために特化しています
- **用途**：Django プロジェクトを 24 時間稼働させる
- **必要**：PythonAnywhere アカウント（無料版で十分）

### 4. GitHub Actions —— 自動デプロイツール

![](images/github-actions-placeholder.png)

- **説明**：GitHub 組み込みの自動化ツール
- **用途**：コードを GitHub にプッシュすると、自動的に PythonAnywhere にサイト更新を通知
- **必要**：GitHub アカウントに付属、追加料金不要

## 三、準備

### プロジェクト構成を確認

プロジェクトルートディレクトリに以下の重要なファイルがあることを確認します：

```
myblog_Django/
├── manage.py              # Django 管理スクリプト
├── requirements.txt        # Python 依存関係一覧
├── myblog/
│   ├── settings.py         # Django 設定ファイル
│   ├── wsgi.py             # サイトエントリーファイル
│   └── urls.py             # URL ルーティング
├── blog/                   # ブログアプリケーション
├── users/                  # ユーザーアプリケーション
├── comments/               # コメントアプリケーション
└── .github/workflows/      # GitHub Actions 設定（自動デプロイ用）
```

> `requirements.txt` ファイルがない場合は、ローカルターミナルで以下を実行：
> ```bash
> pip install django django-ckeditor-5 pillow gunicorn whitenoise
> pip freeze > requirements.txt
> ```

## 四、第一步：コードを GitHub にアップロード

### 4.1 GitHub でリポジトリを作成

1. [github.com](https://github.com) にログイン
2. 右上の **+ → New repository** をクリック
3. リポジトリ名に `myblog_Django` を入力、**Public** を選択
4. いずれのオプションもチェックせず、**Create repository** をクリック

![](images/create-repo-placeholder.png)

### 4.2 ローカルコードを GitHub にプッシュ

ローカルPCのターミナル（プロジェクトディレクトリ内）で、以下のコマンドを順に実行：

```bash
# Git の初期化（まだの場合）
git init

# すべてのファイルを Git に追加
git add .

# コミット
git commit -m "first commit"

# リモートリポジトリを関連付け（あなたの GitHub ユーザー名に置き換え）
git remote add origin https://github.com/あなたのユーザー名/myblog_Django.git

# GitHub にプッシュ
git push -u origin main
```

> デフォルトブランチが `main` ではなく `master` の場合は、上記の `main` を `master` に置き換えてください。
> すでに過去にコミットしている場合は、`git push` を直接実行してください。

## 五、第二步：PythonAnywhere にデプロイ

### 5.1 登録してログイン

1. [pythonanywhere.com](https://www.pythonanywhere.com) を開く
2. アカウントを登録（無料版で十分）
3. 登録後、次のようなドメインが発行されます：`あなたのユーザー名.pythonanywhere.com`

![](images/pa-signup-placeholder.png)

### 5.2 Bash コンソールを開く

ログイン後、上部メニュー **Consoles → Bash** をクリックして、コマンドラインウィンドウを開きます。

![](images/pa-console-placeholder.png)

### 5.3 コードをクローンして依存関係をインストール

開いた Bash コマンドラインで、以下のコマンドを順に実行：

```bash
# GitHub からプロジェクトをクローン
git clone -b main https://github.com/あなたのユーザー名/myblog_Django.git

# プロジェクトディレクトリに移動
cd myblog_Django

# 仮想環境を作成（隔離された Python 実行環境）
python3 -m venv venv

# 仮想環境を有効化
source venv/bin/activate

# すべての依存関係をインストール
pip install -r requirements.txt
```

### 5.4 静的ファイルとデータベースの準備

引き続き Bash で実行：

```bash
# すべての静的ファイルを収集（CSS、JS、画像など）
python manage.py collectstatic --noinput

# データベーステーブルを作成
python manage.py migrate

# 管理者アカウントを作成（プロンプトに従ってユーザー名、メール、パスワードを入力）
python manage.py createsuperuser
```

### 5.5 Web アプリケーションの設定

上部メニュー **Web** をクリックし、Web アプリケーション管理ページに移動します。

![](images/pa-web-page-placeholder.png)

**Add a new web app** をクリックし、次の操作を行います：

1. **Manual Configuration**（手動設定）をクリック
2. **Python 3.12** を選択
3. **Next** をクリックして作成完了

### 5.6 設定情報を入力

作成完了後、Web ページで以下の設定項目を見つけて変更します：

| 設定項目 | 入力内容 |
|---------|---------|
| **Code**（ソースコードディレクトリ） | `/home/あなたのユーザー名/myblog_Django` |
| **Working directory**（作業ディレクトリ） | `/home/あなたのユーザー名/myblog_Django` |
| **Virtualenv**（仮想環境） | `/home/あなたのユーザー名/myblog_Django/venv` |

![](images/pa-settings-placeholder.png)

### 5.7 WSGI ファイルを修正

Web ページで **WSGI configuration file** を見つけ、リンクをクリックして編集ページに移動します。

**ファイルの内容をすべて削除**し、以下のコードに置き換えます：

```python
import os
import sys

# プロジェクトパス
path = '/home/あなたのユーザー名/myblog_Django'
if path not in sys.path:
    sys.path.append(path)

# Django の設定ファイルを指定
os.environ['DJANGO_SETTINGS_MODULE'] = 'myblog.settings'

# 本番環境ではデバッグモードをオフ
os.environ['DJANGO_DEBUG'] = 'False'

# Django を起動
from django.core.wsgi import get_wsgi_application
application = get_wsgi_application()
```

> **注意**：`あなたのユーザー名` を実際のユーザー名（例：`EthanBAI`）に置き換えてください。

**Save** をクリックして保存します。

### 5.8 静的ファイルマッピングを追加

同じページを下にスクロールし、**Static files** セクションを見つけます：

![](images/pa-static-files-placeholder.png)

2つのレコードを追加します：

| URL | Directory |
|-----|-----------|
| `/static/` | `/home/あなたのユーザー名/myblog_Django/staticfiles` |
| `/media/` | `/home/あなたのユーザー名/myblog_Django/media` |

### 5.9 サイトをリロード

ページ上部の緑色の **Reload** ボタンをクリックします。

![](images/pa-reload-placeholder.png)

### 5.10 サイトにアクセス

ブラウザを開いて、次のURLにアクセス：

```
https://あなたのユーザー名.pythonanywhere.com
```

すべて正常に動作していれば、ブログが公開されています！

## 六、第三步：自動デプロイの設定

コードを更新するたびに手動で PythonAnywhere にログインするのは面倒です。以下で **GitHub Actions** を使って自動デプロイを設定します。

### 6.1 PythonAnywhere にデプロイスクリプトを作成

PythonAnywhere の **Bash Console** に戻り、以下を実行：

```bash
cd ~
nano deploy.sh
```

以下の内容を貼り付け：

```bash
#!/bin/bash
# 自動デプロイスクリプト —— 最新コードの取得、依存関係の更新、データベースのマイグレーション
cd /home/あなたのユーザー名/myblog_Django

# GitHub から最新コードをプル
git pull origin main

# 仮想環境を有効化
source venv/bin/activate

# 依存関係を更新
pip install -r requirements.txt -q

# データベースマイグレーションを実行
python manage.py migrate --noinput

# 静的ファイルを収集
python manage.py collectstatic --noinput

echo "コードの更新が完了しました！"
```

> **注意**：`あなたのユーザー名` を実際のユーザー名に置き換えてください。

`Ctrl+X` を押し、次に `Y`、さらに `Enter` を押して保存します。

その後、以下を実行：

```bash
chmod +x deploy.sh
```

### 6.2 スケジュールタスクを作成（オプション）

PythonAnywhere のスケジュールタスクは有料機能です。課金したくない場合はこの手順をスキップしてください。以後は GitHub Actions に完全に依存します。

### 6.3 GitHub リポジトリに Secrets を追加

Secrets は暗号化された機密情報で、GitHub Actions が PythonAnywhere に接続するために使用します。

#### Step 1：PythonAnywhere API Token を生成

1. PythonAnywhere にログイン
2. 右上のアバター → **Account** をクリック
3. **API Token** タブをクリック
4. **Create new API token** をクリック
5. 生成されたトークン（長い文字列）をコピー

![](images/pa-api-token-placeholder.png)

#### Step 2：GitHub に Secrets を追加

1. GitHub リポジトリを開く：`https://github.com/あなたのユーザー名/myblog_Django`
2. **Settings** タブをクリック
3. 左側メニューの **Secrets and variables → Actions** を選択

![](images/github-secrets-placeholder.png)

4. **New repository secret** をクリックし、2つの secret を追加：

| Name | Value |
|------|-------|
| `PA_API_TOKEN` | 先ほど PythonAnywhere からコピーしたトークン |
| `PA_USERNAME` | あなたの PythonAnywhere ユーザー名（例：`EthanBAI`） |

### 6.4 GitHub Actions 設定の説明

プロジェクト内の `.github/workflows/deploy.yml` ファイルには、自動デプロイのフローがすでに設定されています。その動作フローは以下の通りです：

```
コードを GitHub にプッシュ
      ↓
GitHub Actions が起動
      ↓
API 経由で PythonAnywhere に通知
      ↓
PythonAnywhere がデプロイスクリプトを実行
（コード取得 → 依存関係インストール → データベースマイグレーション → 静的ファイル収集）
      ↓
サイトが自動更新完了 🎉
```

設定ファイルの内容は以下の通りです（通常は変更不要）：

```yaml
name: Deploy to PythonAnywhere

on:
  push:
    branches: [main]          # main ブランチにプッシュがあったときに実行

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - name:  PythonAnywhere デプロイをトリガー
        run: |
          curl -H "Authorization: Token ${{ secrets.PA_API_TOKEN }}" \
               -H "Content-Type: application/json" \
               -X POST \
               "https://www.pythonanywhere.com/api/v0/user/${{ secrets.PA_USERNAME }}/webapps/${{ secrets.PA_USERNAME }}.pythonanywhere.com/reload/"
```

### 6.5 自動デプロイをテスト

1. ローカルプロジェクトで任意の内容を変更（例：ページのテキストを変更）
2. コミットしてプッシュ：

```bash
git add .
git commit -m "自動デプロイのテスト"
git push origin main
```

3. GitHub リポジトリを開く → **Actions** タブで、実行中のワークフローを確認

![](images/github-actions-running-placeholder.png)

4. ワークフローが緑色のチェックマークになるまで待機（約30秒）
5. サイトをリフレッシュして、変更が反映されていることを確認

## 七、よくある問題

### Q：サイトに 502 Bad Gateway と表示される

**原因**：WSGI 設定に問題があるか、依存関係が完全にインストールされていません。

**解決方法**：
1. PythonAnywhere Web ページの **Error log** をクリックしてエラーログを確認
2. よくある原因：`settings.py` で `DEBUG = False` に設定されているが、`ALLOWED_HOSTS` が設定されていない
3. `settings.py` に以下を追加：`ALLOWED_HOSTS = ['あなたのユーザー名.pythonanywhere.com', 'localhost']`

### Q：静的ファイルが表示されない（CSS、画像がない）

**原因**：静的ファイルのパスが正しく設定されていません。

**解決方法**：Web ページの Static files 設定が正しいか確認：
- `/static/` → `/home/あなたのユーザー名/myblog_Django/staticfiles`
- その後 `python manage.py collectstatic` を再実行

### Q：データベースエラー

**原因**：データベースマイグレーションが実行されていません。

**解決方法**：Bash で `python manage.py migrate` を実行

### Q：GitHub Actions の実行が失敗する

**原因**：Secrets の設定ミスまたはネットワーク問題。

**解決方法**：
1. GitHub リポジトリ Settings → Secrets で `PA_API_TOKEN` と `PA_USERNAME` が正しいか確認
2. PythonAnywhere Account → API Token ページでトークンが有効か確認

## 八、日常的な使用フロー

上記の設定後、日々のワークフローは非常にシンプルになります：

```
コードを書く → git add → git commit → git push
                                      ↓
                             サイトが自動更新 ✅
```

PythonAnywhere に手動でログインしてコードをプルしたり、データベースをマイグレーションしたりする必要はもうありません。

# Vibe Coding で多言語サイトを作る——たった1つのルールで翻訳の混乱を解決した方法

> サイトが1つの言語から3つの言語になるとき、混乱が始まります。

---

## 「中国語だけでいい」から「翻訳も必要？」へ

このブログサイトの最初のアイデアはとてもシンプルでした：中国語で記事を書き、中国語のユーザーに見てもらう、すべて中国語で。

ところが、それだけではダメだと気づきました。

一つは中国語ができない友人もいること。二つ目は、自分のプロジェクトをもっと多くの人に見てもらいたいこと。三つ目は、英語と日本語のライティングも練習したいこと。そこで決断しました：**中日英の3言語同時運用**。

そして、ハマりました。

---

## 混乱はどのように始まったか

最初はルールなどなく、思いつくままに変更していました。

ナビゲーションバーの「关于」を「关于我」に変更——中国語のテンプレートだけを変更し、英語と日本語のページは「About」と「について」のまま。「とりあえず中国語だけ直して、後で残りの2つもやろう」と思っていました。

後で？ 二度と戻ってきませんでした。

1ヶ月後にコードを見ると、`base.html` の中に3つの言語が混在していました：中国語のハードコード、英語の半翻訳、日本語は未着手。`.po` ファイルには十数件の未翻訳エントリが残っていました。自分でもどれが翻訳済みでどれが未対応なのか区別がつきません。

**これがルールなしの結果です。**

---

## 問題はどこにあるのか

Vibe Coding でサイトを作る特徴は一つ：**速い**ことです。

AI に「ナビゲーションバーを直して」と言えば、10秒で修正してくれます。修正後に良い感じだと確認したら、他のことをやりに行く。英語と日本語のページは？ 忘れてしまいました。

これは態度の問題ではなく、フロー（流れ）の問題です。Vibe Coding はコード修正を簡単にしすぎていて、「中国語を直したら、他の2つの言語も直さなければ」ということを忘れさせてしまうのです。

しかも AI は自発的に注意してくれません——頼まれたことだけをやります。「'关于'を'关于我'に変えて」と言えば、その1箇所だけを変更します。あなたのサイトに3つの言語があることを AI は知らないのです。

---

## 解決策：たった1つのルール

解決方法は「覚えておく」ことではなく、**ルール**を設けることです。

私はプロジェクトの `.trae/skills/` ディレクトリに1つのルールを書き、AI が変更を実行する前に自動的に参照するようにしました。ルールの核心は一言です：

> **何かを変更する前に、自分に問いかけよう：この変更はいくつの言語に関係する？**

このルールはいくつかの部分で構成されています：

### 1. どんな場合に発動するか

UI のテキストだけではありません。以下の変更はすべて言語同期に関係します：

- ナビゲーションバー、ボタン、タイトルなどのインターフェーステキストの変更
- ブログ記事の修正・公開
- 新しいページテンプレートの追加
- ページ上の説明文の変更

### 2. UI テキストを変更する標準手順

```
コードを修正 → makemessages で翻訳を抽出 → 3つの .po ファイルを編集 → .mo ファイルをコンパイル
```

簡単に言えば：コード内で `{% trans "xxx" %}` や `_('xxx')` を使って翻訳対象のテキストをマークし、Django のコマンドで `.po` ファイルに抽出して、1件ずつ翻訳を記入し、最後にコンパイルします。

### 3. ブログコンテンツの処理ロジック

ブログ記事は `.po` ファイルでは管理しません。3つの言語バージョンを手動で管理する必要があります：

```
blog/content/
├── zh-hans/article.md    ← 中国語原文
├── en/article.md         ← 英語翻訳
└── ja/article.md         ← 日本語翻訳
```

ルールの約束：**少なくとも中国語版は完全にすること。英語と日本語は簡略版でもよいが、空欄は不可。**

### 4. 変更後のチェックリスト

これは「愚直」チェックリストです。変更のたびに照らし合わせて確認します：

- 3つの言語すべて翻訳しましたか？
- `.po` ファイルはすべて記入しましたか？
- `.mo` ファイルにコンパイルしましたか？
- 言語を切り替えて表示を確認しましたか？

---

## 効果はどうか

ルールを skill に書き込んだ後、AI に何か変更を頼むと、自動的にルールに従って実行するようになりました。

例えば「トップページのタイトルを '探索日志' に変更して」と言った場合：

以前：AI は中国語だけ変更 → 完了 → 英語と日本語は未着手。

今：AI がルールを読む → 多言語に関係することを認識 → 中国語を変更 → 翻訳を抽出 → 私が英語と日本語の翻訳を記入するのを待つ → コンパイル → 完了。

**「人が覚える」から「ルールが実行する」へと変わりました。**

---

## これらの経験はあなたにも役立つかもしれません

あなたも多言語サイトを作っているなら、技術スタックに関わらず、以下のアドバイスが役立つかもしれません：

1. **最初から翻訳フレームワークを構築しておく。** たとえ今は1言語だけでも、i18n の枠組みを整えておきましょう。後から言語を追加するのは設定変更だけで済み、再構築は不要です。
2. **ルールをプロジェクト内に書く。** どこかのドキュメントに隠さず、AI が見える場所（例：`.trae/skills/`、`.cursorrules`）に置きましょう。
3. **チェックリストはドキュメントを読み返すより速い。** 変更のたびにいくつかのチェックボックスを確認する方が、ルールを最初から読み直すより効率的です。
4. **人間は怠けたがるもの。** それは態度の問題ではなく、フローの問題です。ルールで記憶を代替し、自動化で手作業を代替しましょう。

---

## 付録：ルールファイルの置き場所

私は Trae IDE を使っています。ルールは以下に置いています：

```
.trae/skills/multi-lang-maintenance/SKILL.md
```

Cursor を使っているなら、対応する場所は：

```
.cursorrules
```

または、1つのマークダウンファイルに書いて、コードを変更する前に毎回自分で確認するのでも構いません。大事なのはツールではなく、**ルールがあるかどうか**です。

> ルールのない多言語サイトは、3ヶ月後には自分でもわけがわからなくなります。😅

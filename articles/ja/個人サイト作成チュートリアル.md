# 個人サイト作成チュートリアル：アイデアから公開まで

> 誰でも自分のウェブサイトを持てる時代。今はかつてないほど簡単です。

---

## 一、あなたはどのタイプのサイトが必要？

まずは技術のことを考えずに、何をしたいかを明確にしましょう。

### 3つの一般的な個人サイト

```
個人サイト
 ├─ 静的ポートフォリオサイト —— プロジェクト、作品集、履歴書の展示
 ├─ ブログ          —— 文章を書き、考えを記録し、知識を共有
 └─ 複合型      —— トップページ表示 + ブログ機能
```

### どう判断する？

自分に問いかけてみてください：

> **記録したり共有したりしたいコンテンツはありますか？**

- **ある** → ブログを作りましょう。プロジェクトを完了した、本を読んだ、何か考えた——それを書き留めて人に伝えたい。
- **ない** → 静的ポートフォリオサイトで十分です。プロジェクトへのリンク、自己紹介、連絡先を載せましょう。

> 最初に迷っているなら、静的サイトから始めてください。後で書きたいことができたら、いつでもブログ機能を追加できます。

---

## 二、サイトを作るには何が必要？

「フロントエンド」「バックエンド」といった言葉に尻込みする必要はありません。実はとてもシンプルです：

### レストランに例えると

```
サイト = レストラン
 ├─ フロントエンド = ホール、内装、メニュー、目に見えるすべて
 │    ├─ テーブルや照明 = CSS（スタイル）
 │    ├─ メニューの料理分類 = HTML（構造）
 │    └─ ウェイターの案内 = JavaScript（インタラクション）
 │
 └─ バックエンド = 厨房、倉庫、見えないけどすべてを決める部分
      ├─ 冷蔵庫の食材 = データベース（記事、ユーザー情報）
      ├─ シェフの調理工程 = サーバーロジック（登録、ログイン、検索）
      └─ 水道・ガス・電気 = サーバー（24時間稼働のバックアップ）
```

### 個人サイトに最低限必要なもの：

| 要素 | 説明 | 必須？ |
|------|------|--------|
| **ドメイン** | サイトのアドレス（例：`yourname.com`） | 推奨 |
| **フロントエンドページ** | トップページ、Aboutページ、作品紹介 | ✅ |
| **スタイル** | 見やすい色使い、レイアウト、アニメーション | ✅ |
| **ホスティング** | サイトを24時間オンラインに | ✅ |
| **データベース** | 記事やコメントの保存 | ブログに必要 |
| **管理画面** | 記事を書く管理インターフェース | ブログに必要 |

## 三、今どれだけ簡単にサイトが作れるか？

以前、サイトを作るには以下が必要でした：
1. HTML / CSS / JavaScript を学ぶ
2. フレームワークを学ぶ（React / Vue / Django）
3. サーバーデプロイを学ぶ
4. ドメイン設定、HTTPS設定

今は **Vibe Coding**（AI を使ってコードを書く）のおかげで、流れが変わりました：

```
アイデアが浮かぶ
    ↓
自然言語で AI に説明（例：「個人ページを作って」）
    ↓
AI がコードを生成
    ↓
調整・修正
    ↓
ワンクリックデプロイ
```

**難しくなくなったのは技術ではなく、アイデアです。**

> 何を作りたいかわからないなら、まずは他の人のサイトを見てみましょう。

## 五、スタイルについて

### まず最も重要な考え方

> **サイトは他人に見せるためのもの。コンテンツが核であり、派手なスタイルは必要ありません。**

ある著名な開発者のサイトを見てみてください：\[開発者サイトへのリンク\]

派手なアニメーションや複雑なレイアウトはなくても、コンテンツがしっかりしていて読みやすい。それが良いサイトです。

> スタイルはコンテンツに仕えるものです。まずコンテンツをしっかり書き、スタイルは「きれいで読みやすい」だけで十分です。

### さらに一歩進みたい場合

「きれいで読みやすい」に飽き足らず、より質感のあるサイトを作りたい場合は、以下の方法を参考にしてください：

```
第 1 版：他の人のレイアウトを参考に、機能を作る
     ↓
第 2 版：色を変えて、フォントを変更する
     ↓
第 3 版：余白を調整し、アニメーションを追加する
     ↓
第 4 版：レイアウトを再構成し、スタイルを変える
     ↓
……第 20 版まで繰り返す
```

**目標を設定しましょう：20バージョン改良する。**

一度に全部やるのではなく、しばらく間を置いてから再デザインする。毎回少しずつ良くなっていきます。

### 具体的にどう改良するか？

1. **参考 → 模倣 → 革新**
   - まず好きなサイトのレイアウトを真似る
   - なぜそれが見栄えするのか理解する
   - そして自分の要素を加える

2. **AI にスタイルを生成してもらう**
   - 「5種類の異なる配色案をください」
   - 「このページをガラスモーフィズム風にしてください」
   - 「ナビゲーションバーをよりモダンにしてください」

3. **フォントを変えるだけで印象が変わる**
   - 日本語フォントのおすすめ：Noto Sans JP、Noto Serif JP
   - 英字フォントのおすすめ：Inter、JetBrains Mono

4. **ミニマルは決して間違えない**
   - 余白を多めに
   - 色数を減らす（メインカラーは3色以内）
   - 字間・行間を読みやすく調整

## 六、よくある落とし穴（絶対に踏まないで）

サイト作りの途中で多くの人が挫折するのは、難しさのせいではなく、以下の落とし穴にはまるからです。

### 落とし穴ゼロ：サイトを作る目的を忘れる

> 個人サイトを作るのは、**自分を表現し、印象を残すため**です。

どんなプロジェクトをやったか、どんな考えがあるか、何が得意か——それをサイトで表現し、見た人の記憶に残ること。

でも、一つ覚えておいてほしい：

> **鉄は熱いうちに打て。自分自身の実力あってこそ。**

サイトはあくまでショーケースであり、中身が重要です。展示できるプロジェクトがなく、書けるコンテンツもなければ、サイトがどんなに見栄えしても空虚です。

**正しい順番：**

```
先にコンテンツ（プロジェクト、作品、考え）を用意
    ↓
その後サイトを作る（それらを展示する）
    ↓
継続的に更新（コンテンツが増えるほど、サイトも充実）
```

> 以下の落とし穴は、すべてこの順番を逆にしたことが原因です。

### 落とし穴一：基礎を固めてから始めようとする

> 「HTML、CSS、JavaScript、React、Django……全部勉強してから始めよう。」

**結果**：何ヶ月も勉強し続け、基礎は終わらず、プロジェクトはいつまでも始まらない。

**正しい方法：**

```
欲しい効果 → やり方を調べる → 作ってみる → わからないことが出たら → その場で学んで使う
```

> 「学んでからやる」ではなく、「やりながら学ぶ」。必要なのは「十分に使えること」であり、「完璧にマスターしてから動く」ことではありません。

### 落とし穴二：たくさん学んだけど、使わなかった

> 「3週間かけて React のエコシステムを全部学んだのに、結局静的テンプレートをちょっと修正して公開した。」

**結果**：学んだことは全部忘れ、やる気も尽きた。

**正しい方法：**
- 始める前に考える：このサイトに本当に必要なものは何か？
- 静的サイトなら、バックエンドを学ぶ必要はない。
- ブログなら、Django か WordPress のどちらか一つで十分。
- **今必要なものだけを学び、出会ってからその都度学ぶ。**

### 落とし穴三：技術が多すぎて目が回る

検索エンジンで調べれば、サイト作成の技術は何十種類もある：

```
フロントエンド：React、Vue、Svelte、Next.js、Nuxt、Astro、Hugo……
バックエンド：Django、Flask、FastAPI、Spring Boot、Express、Ruby on Rails……
データベース：MySQL、PostgreSQL、MongoDB、SQLite……
デプロイ：AWS、Vercel、Netlify、PythonAnywhere、Railway……
```

**結果**：選択肢が多すぎて混乱し、結局やめてしまう。

**覚えておいてほしい：どんなに技術が変わっても本質は同じ。**

| レイヤー | 本質 | 何のフレームワークでも |
|---------|------|---------------------|
| フロントエンド | ページ表示、ユーザー操作処理 | 結局は HTML + CSS + JS |
| バックエンド | データ処理、ビジネスロジック | リクエスト受信 → 処理 → レスポンス返却 |
| データベース | データ保存 | 追加・削除・更新・検索 |

> **最も使い慣れた言語を選び、そのエコシステムを使えば十分です。** Python ができるなら Django、JS ができるなら Next.js。技術は道具であって、目的ではありません。

### 落とし穴四：ゼロから独自スタイルを作ろうとする

> 「誰とも違う、オンリーワンのサイトをデザインするんだ。」

**結果**：真っ白なエディタを一日中眺めて、何も書けない。

**正しい方法：**

```
まず真似る → 次に改良 → 自分のスタイルを形成
```

- 素敵なナビゲーションバーを見つけた？真似しよう。
- 好みの配色がある？真似しよう。
- 良いレイアウトがある？真似しよう。

> 「真似る」は「パクリ」ではなく「学び」です。複数の好きなデザインを組み合わせ、自分のコンテンツに置き換えれば、自然と自分のスタイルができていきます。

**目標を設定しよう：20バージョン改良する。**
最初のバージョンはとても見苦しいかもしれない。それでいい。10版目には少し良くなり、20版目には好きなデザインになっているはずです。

---

## 七、まとめ

```
サイトを作る正しい順番：

1. 何をしたいか明確にする（静的サイトかブログか）
2. 他の人のサイトを参考にし、インスピレーションを得る
3. AI を使って素早く最初のバージョンを作る
4. 公開して、他の人がアクセスできるようにする
5. 継続的に改良する。目標は20バージョン
6. 徐々に自分のスタイルを形成する
```

> 「完璧」になってから公開するのではなく、まず作ってから少しずつ改良していこう。
> 完璧はデザインするものではなく、反復するものだ。
